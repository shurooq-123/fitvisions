# Session, history and admin changes — 21 November 2026

- Public authentication/welcome routes hide the account header even if Firebase retains an authenticated session. Signed-in routes show the fixed header and Back control outside scrolling content. Logging out still clears authentication; hiding a public-route header does not silently delete a valid session.
- History image entries open the avatar/design editor with the saved image as the reference. New records include measurements, gender and design instructions. Legacy entries without measurements need input; old full-resolution images cannot be recovered from a stored preview. Editing creates a new history result and retains the previous one. Subscription access is rechecked.
- Admin user details link to a user-filtered report screen. PDF export/share includes account name/email/phone and the selected activity, payment or feedback records; the general admin reports remain available.
- Editing a catalogue plan atomically creates a new catalogue document and removes the old catalogue listing. Purchased subscription/payment snapshots are never updated or deleted by this operation. Existing holders keep their original price/duration/features until expiry.
- Allowed archive actions use the local authenticated admin server on port 8790 in debug installations. Firebase token verification includes revocation checking; server-side transaction checks caller role, self/admin targets and active subscriptions. Records remain retained; authentication is disabled, refresh tokens revoked and device registrations removed. Repeated calls can finish an interrupted disable step safely. Release builds still require the prepared cloud callable deployment.
- Keep the laptop and admin server online, plus `adb reverse tcp:8790 tcp:8790`. No billing upgrade or service-account secret is embedded. AI/mail processes were not restarted.
